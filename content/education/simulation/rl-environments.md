## A 물리 엔진 위에 학습 문제를 정의한다

MuJoCo가 움직임을 계산하더라도 학습 목표가 자동으로 생기지는 않습니다. 어떤 값을 정책에 보여줄지, 어떤 명령을 받을지, 보상을 어떻게 계산할지, 언제 시도를 끝낼지를 정해야 합니다. 이것이 **강화학습 환경**의 역할입니다.

**Gymnasium**은 이런 환경을 공통 인터페이스로 다루는 라이브러리입니다. `reset()`으로 시도를 시작하고 `step(action)`으로 행동의 결과를 받습니다. MuJoCo는 물리 계산, Gymnasium은 환경의 입출력 약속을 맡을 수 있습니다. MJLab 같은 도구는 로봇 작업과 병렬 학습 환경을 구성하는 기능을 더합니다.

## B reset과 step의 반환값을 읽는다

Gymnasium의 `reset()`은 첫 관측과 추가 정보 `info`를 반환합니다. `step()`은 다음 관측·보상·종료 여부·시간 제한 여부·추가 정보를 반환합니다. `info`는 진단에 쓸 수 있지만 항상 정책 입력에 포함되는 것은 아닙니다.

| 반환값 | 의미 | 로봇 예시 |
|---|---|---|
| observation | 행동 뒤의 관측 | 관절 각도·속도·몸통 기울기 |
| reward | 이번 행동의 보상 | 자세 유지·모션 추종 점수 |
| terminated | 작업 자체의 종료 | 넘어짐 같은 정의된 실패 |
| truncated | 외부 제한에 따른 종료 | 정해 둔 실행 시간 초과 |
| info | 추가 진단 정보 | 개별 보상 항·종료 사유 |

아래는 입출력을 확인하기 위한 명령 예시입니다. 무작위 행동은 학습된 정책이 아니며, 잘 제어되는 결과를 기대하지 않습니다.

```python title="Gymnasium 입출력 확인 예시"
import gymnasium as gym

env = gym.make("Pendulum-v1")
observation, info = env.reset(seed=14)
for _ in range(20):
    action = env.action_space.sample()
    observation, reward, terminated, truncated, info = env.step(action)
    if terminated or truncated:
        observation, info = env.reset()
env.close()
```

`Pendulum-v1`은 Gymnasium의 classic-control 환경입니다. 위 코드 자체가 MuJoCo 실행 예시는 아닙니다. 실제 MuJoCo 환경이나 로봇 작업을 선택할 때는 해당 환경의 설치 요구사항과 입력 정의를 확인합니다.

## C 종료 사유를 나누어 기록한다

넘어짐과 시간 제한은 둘 다 새 에피소드를 시작하는 계기가 되지만 학습에서는 다르게 처리할 수 있습니다. 작업이 끝난 것인지, 계속할 수 있지만 기록을 끊은 것인지에 따라 다음 상태의 가치 사용이 달라집니다. 이 두 값을 합친 옛 `done` 예제와 최신 API를 혼용하지 않습니다.

평가에서도 누적 보상 하나만으로 성공을 판단하지 않습니다. 성공률·넘어지기까지의 시간·관절 제한 초과·실행 시간처럼 작업의 기준을 함께 봅니다. 보상이 커도 의도와 다른 방식으로 점수를 얻는 행동이 나올 수 있습니다.

| 환경 계약 | 학습과 실행에서 일치할 기준 |
|---|---|
| 관측 | 순서·단위·정규화·과거 정보 |
| 행동 | 관절 순서·스케일·명령 제한 |
| 초기화 | 시작 자세·속도·랜덤화 범위 |
| 종료 | 실패 조건·시간 제한·재시작 방식 |

## D Kimodo 응용으로 이어간다

Kimodo는 따라 할 목표 모션을 생성하는 쪽에 쓰입니다. 리타기팅은 그 모션을 Microban의 몸체와 관절에 맞춥니다. 학습 환경은 현재 로봇 상태와 목표를 관측으로 만들고, 동작의 결과를 보상으로 평가합니다.

```flow LR
목표 모션 -> 환경: 로봇과 목표 정의
환경 -> 정책: 현재 관측
정책 -> 구동기 명령: 행동 변환
구동기 명령 -> 물리 계산: 관절과 접촉
물리 계산 -> 환경: 다음 관측과 보상
```

이제 Kimodo 자료를 읽을 때 생성 모델·리타기팅·물리 엔진·정책·관절 제어기의 역할을 각각 구분할 수 있습니다. 학습된 체크포인트를 실행하기 전에는 관측 크기와 순서, 행동의 단위, 제어 주기부터 맞춥니다.
