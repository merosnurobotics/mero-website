## A 화면·물리 계산·ROS는 서로 다른 역할이다

Gazebo는 로봇과 환경의 물리·센서 값을 계산하는 시뮬레이터입니다. GUI는 그 장면을 보여주고, ROS 프로그램은 계산한 센서 값을 받아 판단하거나 제어 명령을 보냅니다. 화면에 로봇이 보여도 ROS 메시지가 자동으로 연결됐다는 뜻은 아닙니다.

```flow LR
월드와 로봇 모델 -> Gazebo 물리 계산: 위치와 접촉 갱신
Gazebo 물리 계산 -> 센서 계산: 사진과 거리와 관절 상태
센서 계산 -> ROS 연결: 필요한 메시지 변환
ROS 연결 -> 제어 노드: 목표와 피드백
제어 노드 -> Gazebo 물리 계산: 구동기 명령
```

MuJoCo와 Gazebo를 모두 필수로 배울 필요는 없습니다. 현재 학습 경로에서는 MuJoCo로 물리·정책의 관계를 익히고, Gazebo는 **ROS 센서·제어 인터페이스가 연결되는 구조**를 이해하는 선택 자료로 둡니다.

## B 호환되는 버전 조합을 한 가지 정한다

기존 ROS 자료는 Ubuntu 22.04 / Humble입니다. 새 Gazebo 입문 환경은 **Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic**을 기준으로 잡습니다. 기존 장치를 바꾸라는 뜻이 아니라 별도 교육 환경의 조합입니다.

공식 호환 표에서 Humble의 기본 조합은 Fortress, Jazzy는 Harmonic입니다. 설치 명령·브리지 메시지·제어 플러그인을 다른 세대와 섞으면 같은 튜토리얼이 아닙니다. Gazebo Classic과 현대 Gazebo도 구분합니다. 새 자료는 현대 Gazebo를 사용합니다.

[공식 ROS–Gazebo 설치 안내](https://gazebosim.org/docs/latest/ros_installation/)에서 해당 OS·ROS 조합을 먼저 확인합니다. 이 자료는 개념 입문이며 새 장치의 설치·센서·모터 통합을 모두 끝내는 프로젝트 매뉴얼이 아닙니다.

## C 로봇 모델과 월드 모델을 구분한다

로봇에는 링크·관절·구동기가 있고, 월드에는 바닥·중력·물체·조명이 있습니다. visual은 보이는 형상, collision은 접촉을 계산할 형상입니다. 질량·관성이 없거나 잘못되면 외형이 맞아도 움직임이 다릅니다.

**URDF**는 로봇의 링크·관절 구조를 표현하는 데 널리 쓰이고, **SDF**는 로봇·센서·월드 설정을 표현합니다. xacro는 반복되는 로봇 설정을 작성할 때 쓰는 도구입니다. 파일 이름을 익히기보다 어느 값이 외형·물리·센서·제어를 정하는지 구분합니다.

첫 튜토리얼은 휴머노이드 전체 대신 바닥 위 작은 물체부터 봅니다. 정지 상태와 떨어지는 상태를 비교하면 중력·충돌·물리 시간의 역할을 확인할 수 있습니다. 공식 [SDF 월드](https://gazebosim.org/docs/harmonic/sdf_worlds/)와 [작은 로봇 만들기](https://gazebosim.org/docs/harmonic/building_robot/)를 이 단계의 실행 자료로 연결합니다.

## D 센서 데이터는 브리지에서 ROS 메시지로 바뀐다

Gazebo Transport와 ROS 2는 서로 다른 메시지 전달 체계입니다. `ros_gz_bridge`는 지원하는 메시지 타입을 변환해 연결합니다. 센서 종류·토픽 이름·메시지 타입·전달 방향을 각각 정합니다.

| 확인할 것 | 의미 |
|---|---|
| Gazebo 쪽 토픽 | 시뮬레이터가 실제로 내보내는 이름 |
| ROS 쪽 토픽 | ROS 노드가 구독하는 이름 |
| 타입 변환 | 센서 값이 어떤 필드로 들어오는지 |
| 방향 | 센서는 Gazebo → ROS, 명령은 반대일 수 있음 |
| 좌표와 시각 | 값의 기준 프레임과 관측 시간 |

첫 센서 튜토리얼에서는 센서 하나만 선택해 Gazebo의 값과 ROS의 값을 같은 뜻으로 읽습니다. [공식 센서 자료](https://gazebosim.org/docs/harmonic/sensors/)와 [ROS 연결 자료](https://gazebosim.org/docs/harmonic/ros2_integration/)가 이어지는 실행 경로입니다. 여러 카메라·IMU·발 접촉을 한 번에 통합하는 것은 프로젝트 단계로 남깁니다.

## E 물리 시간과 실제 시간을 구분한다

시뮬레이션 시간 1초를 계산하는 데 실제 2초가 걸리면 real-time factor는 0.5입니다. 정책을 실제 시간으로만 부르면 물리 시간 기준의 제어 주기가 달라질 수 있습니다. `/clock`과 `use_sim_time`은 ROS 노드가 시뮬레이션 시각을 쓰도록 연결하는 개념입니다.

관절의 상태 인터페이스는 측정 위치·속도 등을 읽는 쪽이고, 명령 인터페이스는 목표를 내보내는 쪽입니다. `ros2_control`과 Gazebo 연결은 이 차이를 다루는 다음 선택 주제입니다. 토픽이 보인다는 사실만으로 관절의 실제 반응까지 확인한 것은 아닙니다.

교육에서는 물리 시간·센서 주기·제어 주기를 구분하고, 같은 값을 서로 다른 프로그램에서 읽는 것까지 이해합니다. 장애물·계단·양팔 조작 월드 제작이나 보유 로봇의 제어 플러그인 작성은 프로젝트에서 수행합니다.
