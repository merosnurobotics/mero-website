## A 물리 계산과 화면 표시를 나눈다

**MuJoCo**는 관절로 연결된 몸체와 접촉의 움직임을 계산하는 물리 엔진입니다. 모델에 질량·관절·바닥·구동기를 정하고 명령을 주면, 다음 순간의 위치와 속도를 계산합니다. 화면을 띄우는 것은 계산 결과를 보는 별도 기능입니다.

학습할 때는 화면 없이 많은 스텝을 계산할 수 있습니다. 화면에 로봇이 나타났다는 사실만으로 제어나 학습이 진행되는 것은 아닙니다. 시간이 늘고, 관절 상태가 바뀌고, 명령이 적용되는지 확인합니다.

이 자료는 MuJoCo 공식 개요와 Python 문서의 기본 구조를 선별해 한국어로 정리했습니다. 예제 모델과 실행 결과는 MERO가 제작했습니다.

## B 모델과 실행 상태를 나눈다

`MjModel`은 XML에서 읽은 몸체·관절·구동기와 계산 설정을 담습니다. `MjData`는 현재 시각·관절 상태·구동기 입력처럼 실행 중 바뀌는 값을 담습니다. 같은 모델을 사용해도 초기 상태가 다른 실행을 만들 수 있습니다.

```flow LR
XML 모델 -> MjModel: 구조와 설정 읽기
MjModel -> MjData: 실행 상태 준비
MjData -> ctrl: 구동기 입력 지정
ctrl -> mj_step: 다음 상태 계산
mj_step -> MjData: 시각과 상태 갱신
```

`mujoco.mj_step(model, data)`가 물리 시간을 한 스텝 진행합니다. `mj_forward()`는 현재 상태에서 필요한 계산을 갱신하지만 시간을 진행하지 않습니다. Viewer의 `sync()`나 렌더러의 `render()`도 물리 스텝을 대신하지 않습니다.

## E Cart-pole의 PID를 직접 비교한다

앞 예제는 관절의 토크로 막대를 돌렸습니다. **Cart-pole**에서는 카트를 좌우로 밀어 막대 아래의 받침점을 움직입니다. 막대가 기울어진 쪽으로 카트를 보내 받쳐 주지만, 너무 멀리 달려가면 균형을 유지해도 실패입니다.

슬라이더의 P·I·D는 **막대 각도**에 적용하는 계수입니다. 카트 위치와 속도에 대한 보정은 모든 조합에서 동일하게 유지합니다. 따라서 막대의 흔들림뿐 아니라 카트 이동도 함께 확인해야 합니다. I를 크게 했다고 항상 결과가 좋아지는 것은 아닙니다.

| 모든 조합에서 같은 조건 | 설정 |
|---|---|
| 초기 기울기 | 0.12 rad, 약 6.9° |
| 물리 계산 / 관찰 시간 | 0.002초 / 최대 8초 |
| 카트 구동력 | ±8 N 제한 |
| 외부 힘 | 3초부터 0.2초 동안 카트에 0.8 N |
| 지속적인 편향 | 막대에 0.025 N·m 토크 |
| 종료 기준 | 막대 각도 0.7 rad 초과 또는 카트 위치 ±2.2 m 초과 |

P가 부족한 조합에서 시작해 D를 바꾸며 흔들림을 비교해 보세요. 다음에는 I를 바꾸고 카트가 얼마나 이동하는지 확인합니다. **8초 유지**는 이 조건에서 종료 기준을 넘지 않았다는 뜻입니다. 오래 안정적으로 유지하거나 카트가 원점에 복귀한다는 의미는 아닙니다.

## F 시간 간격과 제어 주기를 읽는다

이 예제는 물리 스텝마다 제어 명령을 다시 계산합니다. 시간 간격은 0.002초이고, 1,500스텝을 실행해 3초를 계산했습니다. 마지막 관절 각도는 약 0.000028 rad입니다. 단순 진자 모델의 결과이며 실물 로봇 성능을 나타내지 않습니다.

![MuJoCo 진자의 PD 제어 · 3초간 관절 각도](/home/user/MEROsite/private/education-assets/simulation/control.png)

GIF는 초당 20프레임으로 보여주지만, 물리 계산은 초당 500스텝 진행합니다. 화면의 프레임 수와 물리 계산 횟수는 다릅니다. 역진자도 같은 시간 간격으로 3,000스텝을 계산했습니다.

강화학습 환경에서는 정책의 행동 하나를 여러 물리 스텝 동안 유지할 수도 있습니다. 물리 스텝 0.002초를 10번 실행하면 정책의 행동 간격은 0.02초입니다. **물리 계산 주기**와 **정책 실행 주기**를 구분해 기록합니다.

실물과 비교할 때는 질량·마찰·센서 잡음·통신 지연·모터 응답도 확인합니다. 시뮬레이션이 성공했다는 이유만으로 같은 명령을 실물에 그대로 적용할 수 있다고 판단하지 않습니다.
