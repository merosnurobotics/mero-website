# 프로젝트 투입 전 교육: 선별안과 다음 집필 주제

교육의 목표는 로봇의 움직임과 학습 결과를 해석하고, 프로젝트에서 결정해야 할 조건을 알아보는 것이다. 프로젝트의 시연 수집기·정책·SDK 어댑터·과제별 환경을 교육에서 완성하지 않는다. 코드는 개념을 확인하는 보조 수단으로 남긴다.

## 이번에 반영한 범위

- 기존 자료 앞뒤에 좌표·시간·단위·배열, 피드백 응답, 접촉·구동기 한계를 보강했다.
- 딥러닝에 선형 모델 한 번의 업데이트와 선형 보정/MLP 비교를 넣었다. 강화학습에는 작은 환경, 누적 보상, Actor–Critic·PPO의 숫자 예제를 넣었다.
- Kimodo는 강화학습 아래의 사례로 유지한다. 정적 참조 자세의 잔차 제어 사례이며, 춤·포복 전체를 해결한 정책으로 소개하지 않는다. 관측·행동·보상과 평가의 범위를 명시했다.
- VLA 입문은 사진·언어·상태, 행동 표현, 시연, 청크, 닫힌 고리 평가와 RB-Y1 연결의 역할을 다룬다. 실제 장비 적용·시연 수집·학습 성공을 주장하지 않는다.
- Gazebo 입문은 물리·화면·센서·ROS, 모델·월드, 브리지, 시뮬레이션 시간의 역할과 공식 실행 경로를 다룬다. 직접 실행한 Gazebo 튜토리얼로 표기하지 않는다.

## 제안에서 뺀 것

Git/PR·충돌 해결, Python 모듈 설계, 학습 루프 작성, 디버깅, pytest, Hydra 설정, 프로파일러 사용법은 독립 강의로 추가하지 않는다. 환경·터미널의 최소 안내는 기존 실습의 접근을 위해 유지한다. 로그는 도구 사용법보다 성공률·오차·지연을 해석하는 개념에 연결한다.

춤 정책 학습, 포복 전환기, 계단·점프 정책, RB-Y1 어댑터와 데이터 수집기, 대형 VLA 미세조정, 양팔·이동 조작은 프로젝트 과업이다. 교육 자료 수를 늘리기 위해 각각의 구현 매뉴얼을 입문 필수 과정으로 만들지 않는다.

## 다음으로 집필할 자료

| 우선순위·제목 | 교육에서 반드시 이해할 범위 | 프로젝트에 넘길 결정 |
| --- | --- | --- |
| 1. 자세와 모션은 무엇이 다른가 | 관절 자세·루트, 시간·위상, 보간·속도, 참조 추종과 행동 복제의 차이. 같은 두 자세를 0.2초/2초에 잇는 비교 | 춤 모션 선택·리타기팅·추종 정책 |
| 2. 바닥에 닿는 부위가 과제를 바꾼다 | 접촉력·마찰·지지 영역, 정적/동적 균형, 허용/금지 접촉. 서기와 포복에서 같은 몸통 접촉의 의미가 달라지는 예 | 포복 접촉 명세·충돌 조건·종료 기준 |
| 3. 사족보행의 한 주기와 점프의 네 단계 | 지지/스윙, 발끝 여유·착지, 계단 상승/하강 차이, 준비·이륙·비행·착지. 접촉 타임라인으로 설명 | 지형 난도·점프 목표·과제 환경·정책 |
| 4. 원하는 움직임과 구동기 가능한 움직임 | 토크·속도·출력·포화, 관절 범위, 궤적의 시간, 충격과 지연. 단순 수치로 요구 속도·출력 비교 | 보유 로봇의 수행 범위·속도·명령 제한 |
| 5. 시뮬레이터가 아는 값과 로봇이 아는 값 | 상태/관측, IMU·엔코더·카메라, 특권 정보, 잡음·편향·지연, 시스템 식별과 도메인 랜덤화의 역할 | 실제 관측 명세·추정기·랜덤화 범위 |
| 6. 무엇을 바꿔야 학습의 효과를 알 수 있는가 | 고정 기준 제어기, 구성 요소 제거 비교, 초기 상태/학습 seed의 차이, 보상/성공률, 평가 조건 | 프로젝트의 기준 방법·평가 표·반복 실험 |
| 7. 시연의 한 프레임에 어떤 행동을 붙이는가 | 영상·상태·목표 명령의 시각, 절대/상대/손끝 행동, 정규화, 청크와 재계획. 작은 시간표·벡터 비교 | RB-Y1 수집 형식·카메라·팔·그리퍼·어댑터 |
| 8. VLA가 언어를 사용했는지 어떻게 확인하는가 | 동일 장면의 지시 변경, 언어 없는 기준, 에피소드별 분리, 닫힌 고리 오차 누적, 새 물체/새 배치의 차이 | 언어·장면별 평가 조건과 실패 분류 |

1~2를 먼저 만들고 3·7을 각 담당자 경로로 분기한다. 4~6은 각 프로젝트에 필요한 때 공통 보충으로 읽는다. 입문에서 전신 제어·MPC·정책 증류·Nav2·MoveIt 전체를 필수로 요구하지 않는다. 지금 목표의 첫 비교 실험을 이해한 뒤 필요한 심화 주제만 선택한다.

## Gazebo는 세 편의 작은 비교 실습이면 충분하다

입문 다음에는 아래 범위만 실행·캡처한다. 기존 MuJoCo 자료를 대체하거나 초보자에게 여러 시뮬레이터를 모두 필수로 요구하지 않는다.

| 제목 | 확인할 개념 | 교육 결과 |
| --- | --- | --- |
| 보이는 모델과 부딪히는 모델 | 링크·관절, visual/collision, 질량·관성, 로봇/월드 | 단순 모델의 표시와 충돌을 비교한 짧은 GIF |
| 가상 센서도 시각과 좌표계가 있다 | 센서 주기, frame, Gazebo 메시지→ROS 브리지 | 물리 장면·센서 출력·RViz의 대응 캡처 |
| 시뮬레이션 시간을 늦추면 무엇이 달라지는가 | /clock·use_sim_time, real-time factor, 물리/제어/표시 주기 | 같은 물리 시간의 빠른/느린 실행 비교 |

새 교육 기준은 Ubuntu 24.04·ROS 2 Jazzy·Gazebo Harmonic으로 고정한다. 기존 Ubuntu 22.04·Humble 실습은 별도 환경으로 유지한다. 버전 조합의 현재 지원 여부는 집필 시 공식 호환표를 다시 확인한다. 전체 로봇 월드 제작·ros2_control 통합·실물 교체는 프로젝트 작업이다.

## 세 프로젝트의 교육 완료 기준

- 휴머노이드: 자세/모션, 시간/위상, 접촉/지지, 기준 제어기/학습 보정의 역할을 설명한다. 춤과 포복에 같은 종료 조건을 적용할 수 없는 이유를 안다.
- 사족보행: 발의 지지·스윙과 계단·점프의 접촉 단계를 읽고, 구동기의 속도·토크 한계를 목표 동작에 연결한다.
- RB-Y1 VLA: 모델의 입력과 행동, 시연의 정답·시각, 청크와 제어 주기, 언어 활용 평가를 구분한다. SDK 명령 전송과 실제 과제 성공을 구분한다.

학생이 모든 구현을 직접 작성할 필요는 없다. AI가 작성한 코드라도 위 의미와 결과의 한계를 설명하고 프로젝트의 설계 조건을 판단할 수 있어야 한다.
