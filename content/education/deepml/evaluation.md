## A 학습·검증·test의 역할을 나눈다

모델을 학습한 사진에서만 평가하면 실제 성능을 알기 어렵습니다. 데이터는 사용 목적에 따라 나눕니다. **train**으로 가중치를 바꾸고, **validation**으로 모델이나 설정을 고르며, **test**로 마지막에 성능을 확인합니다.

```flow LR
수집한 데이터 -> 학습 데이터: 가중치 수정
수집한 데이터 -> 검증 데이터: 모델과 설정 선택
수집한 데이터 -> 시험 데이터: 선택한 모델의 최종 평가
학습 데이터 -> 후보 모델: 학습
후보 모델 -> 검증 데이터: 비교
후보 모델 -> 시험 데이터: 최종 확인
```

같은 영상의 연속 프레임을 무작위로 나누면 거의 같은 사진이 train과 test에 들어갈 수 있습니다. 같은 물체·같은 촬영·같은 시뮬레이션 장면도 묶어서 분리해야 합니다. 학습에 쓰인 정보가 평가 데이터에 섞이는 문제를 **데이터 누수(data leakage)**라고 합니다.

정규화 기준도 train에서 정한 뒤 validation과 test에 그대로 적용합니다. test 결과를 보면서 설정을 계속 바꾸면 그 데이터는 이미 모델 선택에 영향을 준 셈입니다. 다음 최종 평가에는 새 데이터를 준비합니다.

## B 손실과 실제 성능을 구분한다

손실은 학습을 위한 기준입니다. 동아리 활동에서는 로봇의 작업이 성공하는지에 맞춰 별도의 **평가 지표(metric)**도 정해야 합니다.

| 작업 | 확인할 지표 | 함께 볼 실패 사례 |
|---|---|---|
| 종류 구분 | 정확도·클래스별 정답 비율 | 드문 물체만 계속 틀리는지 |
| 물체 찾기 | precision·recall | 없는 물체를 찾거나 있는 물체를 놓침 |
| 영역 분할 | IoU | 깊이를 읽을 위치까지 잘못 포함하는지 |
| 거리 보정 | 평균 절대 오차·최대 오차 | 가까운 곳과 먼 곳의 오차 차이 |
| 로봇 제어 | 성공률·유지 시간·자세 오차 | 넘어지는 조건·한쪽으로 치우친 움직임 |

**Precision**은 찾았다고 한 것 중 정답의 비율입니다. **Recall**은 실제로 있는 것 중 찾아낸 비율입니다. **IoU**는 예측 영역과 정답 영역의 겹침 정도입니다. 물체를 놓치는 비용과 잘못 잡는 비용이 다르므로 지표 하나만으로 설정을 고르지 않습니다.

모델의 **confidence**는 출력 점수입니다. 0.9라는 점수가 항상 정답 확률 90%를 뜻하지는 않습니다. 숫자가 높아도 실패하는 사진을 함께 살펴봅니다.

## C 조건이 바뀌면 모델도 다시 확인한다

학습 때와 실행 때 입력의 성질이 달라지는 것을 **분포 변화(distribution shift)**라고 합니다. 합성 사진과 실제 사진, 조명이 다른 경기장, 교체한 센서처럼 동아리에서 자주 마주치는 변화입니다.

![정답 거리와 예측 거리 · 같은 센서 조건과 입력 편향을 추가한 조건](/home/user/MEROsite/private/education-assets/deepml/evaluation.png)

앞의 합성 예제는 train 96개, validation 32개, test 32개를 사용했습니다. 검증 손실이 가장 작은 가중치를 선택한 뒤 test를 평가했습니다. 같은 test 입력에 0.12 m 편향만 추가해도 오차가 커집니다.

| 조건 | 평균 절대 오차 |
|---|---|
| 학습 전 · 초기 가중치 | 56.23 cm |
| 학습 후 · 같은 센서 조건 | 0.52 cm |
| 학습 후 · 입력에 0.12 m 편향 추가 | 9.09 cm |

이 값은 설명용 합성 데이터의 실제 실행 결과입니다. 특정 센서나 실물 로봇의 정확도는 아닙니다. 모델이 이미 잘 배운 상태에서도 입력 조건이 달라지면 성능이 달라질 수 있다는 점을 보여줍니다.

객체인식에서는 실패한 사진을 거리·조명·배경·가림별로 모읍니다. 모든 상황에서 더 큰 모델을 고르기보다 부족한 조건의 데이터를 먼저 보완하는 편이 원인을 좁히기 좋습니다.

## D 학습된 모델을 로봇 프로그램에 연결한다

이미 학습된 모델을 새 데이터에 맞춰 추가 학습하는 것을 **미세조정(fine-tuning)**이라고 합니다. 동아리에서는 기존 객체인식 모델을 출발점으로 삼고, 우리 물체와 촬영 환경에 맞춘 데이터로 조정할 수 있습니다. 모델 파일만 바꾸는 것과 입력·정답을 준비해 다시 학습하는 것은 다른 작업입니다.

```flow LR
카메라 -> 전처리: 학습 때와 같은 기준
전처리 -> 모델 추론: 저장된 가중치
모델 추론 -> 결과 변환: 클래스와 영역
결과 변환 -> 깊이와 좌표 변환: 관측점 계산
깊이와 좌표 변환 -> ROS 메시지: 좌표계와 측정 시각
```

추론 시간도 측정합니다. 평균뿐 아니라 느린 프레임이 얼마나 오래 걸리는지 확인합니다. 모델의 처리 시간에 입력 전달·전처리·후처리 시간이 더해져 최종 결과가 늦어질 수 있습니다. 실제 장비에서 측정한 지연을 기준으로 ROS 발행 주기를 정합니다.

사진 속 마스크는 곧바로 모터 명령이 되지 않습니다. [객체 위치 추정](/education/localization/object-localization)에서 깊이와 로봇 위치를 합쳐 지도 좌표로 바꾸고, 그 좌표를 계획·제어 프로그램에 전달합니다. 이제 신경망이 물체 대신 **다음 행동**을 출력하는 강화학습으로 넘어갑니다.
