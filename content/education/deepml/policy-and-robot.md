## A 정책은 경험을 모아 개선한다

신경망 정책의 가중치는 행동의 결과를 모은 경험으로 학습합니다. 먼저 현재 정책으로 환경에서 행동하고, 관측·행동·보상·종료 여부를 저장합니다. 그 기록을 사용해 정책을 수정한 뒤 다시 경험을 모읍니다.

```flow LR
현재 정책 -> 환경에서 실행: 행동 선택
환경에서 실행 -> 경험 기록: 관측과 행동과 보상
경험 기록 -> 정책 학습: 행동의 이후 결과 비교
정책 학습 -> 현재 정책: 가중치 갱신
```

**가치 함수(value function)**는 현재 상태나 관측에서 정책을 따라갔을 때 앞으로 얻을 누적 보상을 추정합니다. 당장 받은 보상만으로 판단하기 어려울 때, 이후 결과를 함께 평가하는 데 사용합니다.

**어드밴티지(advantage)**는 선택한 행동이 보통 기대하던 결과보다 얼마나 좋거나 나빴는지 나타내는 비교 값입니다. 이 차이를 추정해 좋은 결과에 기여한 행동이 더 자주 선택되도록 정책을 수정합니다. 결과의 변동과 추정 오차가 있으므로, 한 번 성공한 행동만 보고 결정하지 않습니다.

## B PPO는 정책 변화의 폭을 조절한다

**PPO**는 로봇 제어에 자주 사용되는 정책 학습 방법 중 하나입니다. 현재 정책으로 모은 경험을 사용해 정책을 개선하되, 이전 정책에서 지나치게 벗어나는 변경의 이득을 제한하는 장치를 둡니다. 한 번의 업데이트로 행동이 크게 바뀌어 성능이 무너지는 문제를 줄이려는 접근입니다.

PPO-Clip은 목적 함수의 일부를 잘라 지나친 변화의 이득을 제한합니다. 모든 행동의 변화량을 물리적으로 제한하거나 성능 개선을 보장하는 기능은 아닙니다. 관절의 실제 범위와 명령 크기는 별도로 제한합니다.

| 역할 | 학습 중 하는 일 | 실행 중 필요한 것 |
|---|---|---|
| 정책 | 관측에서 행동을 선택 | 로봇의 다음 행동 계산 |
| 가치 함수 | 앞으로의 보상 추정 | 일반적인 정책 추론에는 불필요 |
| PPO | 수집한 경험으로 가중치 수정 | 일반적인 제어 주기에는 불필요 |
| 시뮬레이터 | 움직임·접촉·다음 상태 계산 | 시뮬레이션 평가에 사용 |

**On-policy**는 현재 정책으로 얻은 경험을 중심으로 업데이트하는 방식입니다. PPO는 이 범주에 속하며, 한 번 모은 경험에 여러 학습 스텝을 적용할 수 있습니다. **Off-policy**는 이전 정책이나 다른 방식으로 모은 경험도 학습에 활용하는 방식입니다. 여기서는 알고리즘을 모두 비교하기보다 우리 학습 코드가 어떤 경험을 사용하는지 확인합니다.

## C 추론과 관절 제어의 역할을 연결한다

학습이 끝나면 정책의 가중치를 저장합니다. 로봇에서 제어할 때는 현재 관측을 만들고 정책을 실행해 행동을 계산합니다. 매 제어 주기마다 PPO 학습을 다시 실행하는 것은 아닙니다.

```flow LR
센서와 관절 피드백 -> 관측 구성: 순서와 단위를 맞춘다
관측 구성 -> 정책 추론: 저장된 가중치 사용
정책 추론 -> 목표 보정: 행동의 크기와 범위 적용
목표 보정 -> 관절 제어기: 기준 자세에 더한다
관절 제어기 -> 로봇: 모터 명령
로봇 -> 센서와 관절 피드백: 움직인 결과 측정
```

| 맞춰야 할 항목 | 의미 |
|---|---|
| 관측 순서 | 학습한 관절·센서 값의 배열 순서 |
| 행동 순서 | 출력이 어느 관절에 적용되는지 |
| 스케일과 기준 자세 | 정규화된 출력이 실제 목표로 바뀌는 방식 |
| 실행 주기 | 정책 호출 주기와 관절 제어 주기의 관계 |
| 초기화 | 시작 자세·과거 관측·이전 행동의 초기값 |

정책의 출력이 관절 목표인지 토크인지 확인합니다. [PID 제어](/education/control/pid-control)에서 배운 피드백 제어는 신경망 정책의 아래 단계에서도 쓰일 수 있습니다. 정책이 목표를 정하고, 관절 제어기가 목표와 측정값의 차이를 줄이는 구조입니다.

## D 시뮬레이션의 성공을 실물 조건에서 확인한다

시뮬레이터의 질량·마찰·모터 응답·센서 노이즈가 실제 로봇과 완전히 같지는 않습니다. 지연이나 조립 오차도 정책이 받는 관측과 행동의 결과를 바꿉니다. 객체인식에서 조명 변화로 성능이 달라지듯, 로봇 제어도 실행 조건에 영향을 받습니다.

**도메인 랜덤화(domain randomization)**는 학습 중 마찰·질량·지연 같은 조건을 바꾸어 여러 상황을 경험하게 하는 방법입니다. 실제와의 차이를 줄이는 데 도움이 될 수 있지만, 실물 동작을 자동으로 보장하지는 않습니다.

| 확인 단계 | 기록할 것 |
|---|---|
| 저장 정책의 시뮬레이션 재실행 | 초기 상태·시드·관측·행동·성공 여부 |
| 다른 초기 상태와 조건 | 넘어지는 조건·관절 움직임·유지 시간 |
| 실물 입력과 명령 전달 확인 | 관측 순서·단위·통신 지연·명령 범위 |
| 정한 운용 범위에서 실물 평가 | 자세·접촉·성공률·중단 조건 |

정책 성능은 보상 숫자뿐 아니라 실제 움직임으로 확인합니다. 성공한 영상과 함께 실패한 초기 상태도 남깁니다. 모델 파일·로봇 설정·입력 처리 버전이 바뀌면 같은 기록으로 비교해야 원인을 찾을 수 있습니다.

이제 [Microban 모방 강화학습 자료](/education/reinforcement-learning/kimodo-mjwarp)의 관측·행동·보상·PPO 설정을 읽을 수 있습니다. Kimodo 모션은 따라 할 목표를, 리타기팅은 로봇에 맞는 자세를, 물리 시뮬레이션은 움직임의 결과를 제공합니다.
