## stream-and-request | 통신 방식은 기다리는 결과의 성격으로 고릅니다

| 방식 | 잘 맞는 정보 | 완료·진행 확인 |
|---|---|---|
| 토픽 | 영상·관절 상태 | 새 값의 흐름 |
| 서비스 | 조회·짧은 요청 | 요청에 대한 응답 |
| 액션 | 이동·긴 작업 | 수락·피드백·결과 |

## goal-feedback-result | 목표를 받았다는 것과 성공했다는 것은 다릅니다

```timeline v
요청 | 목표 전송 | 클라이언트가 작업을 제안
수락 | 실행 여부 결정 | 서버가 목표를 받아들임
진행 | 피드백 | 현재 진행 상황을 전달
종료 | 최종 결과 | 성공·실패·취소 상태 확인
```

취소 요청을 보냈다면 실제 취소 결과까지 확인해야 합니다.

## observe-boundaries | 목표가 멈춘 경계를 찾는 순서

```flow LR
목표 생성 -> 서버 수락: 요청
서버 수락 -> 작업 실행: 입력 확인
작업 실행 -> 최종 결과: 상태 전달
```

어느 화살표까지 정상인지 확인한 뒤 첫 실패 경계의 조건을 살펴봅니다.
