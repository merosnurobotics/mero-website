## A 로봇 프로그램의 역할을 먼저 나눈다

센서는 주변과 몸의 상태를 측정합니다. 추정은 측정값을 위치·속도 같은 정보로 바꾸고, 계획은 목표와 다음 움직임을 정합니다. 제어는 목표와 실제 상태의 차이를 보고 구동기 명령을 고칩니다.

```flow LR
센서 -> 추정: 측정값과 시각
추정 -> 계획: 현재 위치와 물체
계획 -> 제어: 목표 위치와 속도
제어 -> 구동기: 전류와 토크와 위치 명령
구동기 -> 센서: 움직인 결과
```

사진에서 물체를 찾았다고 곧바로 모터를 움직이지 않습니다. 물체 좌표와 로봇 좌표를 맞추고 목표를 선택한 뒤 제어로 연결합니다. ROS는 이 프로그램 사이에서 메시지를 전달합니다. 딥러닝은 인식에, 강화학습은 행동 선택에 쓸 수 있습니다.

## B 원격 접속 전에 내 컴퓨터에서 Python을 실행한다

터미널은 명령을 입력하는 창입니다. **현재 작업 경로**는 명령이 파일을 찾는 기준입니다. `pwd`는 현재 경로를, `ls`는 파일 목록을 보여줍니다. `cd 폴더`는 그 폴더로 이동하고 `cd ..`는 상위 폴더로 이동합니다. `/home/robot/lab`은 절대 경로, `lab/demo.py`는 현재 경로 기준의 상대 경로입니다.

아래는 Linux·macOS의 bash/zsh 예제입니다. Ubuntu에서 venv 생성이 안 되면 `sudo apt install python3-venv`로 설치합니다. Windows는 Python 설치 후 `py -m venv .venv`와 PowerShell의 `.venv\Scripts\Activate.ps1`을 사용합니다.

```bash
mkdir -p mero-first-run
cd mero-first-run
python3 -m venv .venv
source .venv/bin/activate
python -c "import sys; print(sys.executable)"
python -m pip --version
python -c "print('MERO Python OK')"
```

첫 출력에 이 폴더의 `.venv` 경로가 보이고 마지막에 `MERO Python OK`가 나오면 로컬 실행이 준비됐습니다. 가상환경은 프로젝트별 Python 패키지를 나눕니다. `source`는 현재 셸에 활성화 설정을 읽고, `python -m pip`는 지금 선택한 Python에 설치합니다. `deactivate`로 빠져나옵니다.

편집기로 `demo.py`를 열어 `print('hello')`를 저장하고 같은 폴더에서 `python demo.py`를 실행합니다. 계속 실행하는 프로그램은 해당 터미널의 `Ctrl+C`로 종료합니다. 이 단계에는 Jetson·ROS·모터가 필요 없습니다. 뒤의 SSH부터 원격 장치를 사용합니다.

## C 배열의 모양을 먼저 읽는다

리스트는 값을 순서대로 담습니다. NumPy 배열과 PyTorch 텐서는 숫자를 여러 축으로 묶고 계산하는 도구입니다. **shape**는 각 축의 길이입니다. 값의 개수뿐 아니라 축이 무엇을 뜻하는지 알아야 합니다.

| 예시 | shape | 축의 뜻 |
|---|---|---|
| 거리 하나 | `(1,)` | 입력 값 1개 |
| 거리 4개를 한 번에 처리 | `(4, 1)` | 배치 4개 × 각 입력 1개 |
| RGB 사진 | `(480, 640, 3)` | 높이 × 너비 × 채널 |
| PyTorch의 RGB 사진 2장 | `(2, 3, 480, 640)` | 배치 × 채널 × 높이 × 너비 |

배열 `a = [[1, 2], [3, 4], [5, 6]]`의 shape는 `(3, 2)`입니다. `a[1]`은 두 번째 행 `[3, 4]`입니다. NumPy 배열의 `a[:, 0]`은 모든 행의 첫 열 `[1, 3, 5]`, `a[0:2]`는 앞 두 행입니다. Python 리스트에는 `a[:, 0]`을 그대로 쓰지 않습니다.

배치는 함께 계산할 입력 묶음입니다. 배열을 펼치거나 축을 바꿀 때 원래 뜻을 잃지 않아야 합니다. 이미지의 높이·너비·채널 순서를 바꾸는 것과 픽셀을 0~1로 만드는 것은 다른 처리입니다.

## D 단위와 시간 간격을 맞춘다

길이 100 mm는 0.1 m, 각도 180°는 π rad입니다. 모터가 60 rpm으로 돌면 초당 한 바퀴이므로 약 6.283 rad/s입니다. 주기 50 Hz는 1초에 50회, 시간 간격 `dt`는 0.02초입니다.

엔코더가 출력축 한 바퀴에 1,000 count를 내고 0.1초 동안 25 count 증가했다면 `25 / 1000 / 0.1 = 0.25 rev/s = 15 rpm`입니다. 데이터시트의 count가 모터축 기준인지 출력축 기준인지, x1/x2/x4 중 어느 방식인지 확인해야 기어비를 두 번 적용하지 않습니다.

모터 전압·PWM은 구동 입력, 전류는 토크와 관련된 측정, 엔코더는 회전 위치를 읽는 센서입니다. 각도 차이를 시간 간격으로 나누면 평균 각속도를 구합니다. 측정 시각이 다르면 같은 변화량도 다른 속도가 됩니다.

## E 같은 점을 다른 좌표계로 표현한다

ROS의 일반적인 몸체 축은 x가 앞, y가 왼쪽, z가 위입니다. 카메라 optical frame은 x가 오른쪽, y가 아래, z가 앞이므로 그대로 같은 축으로 읽으면 안 됩니다. 양의 yaw는 z축을 기준으로 오른손 규칙에 따라 회전합니다.

로봇이 map에서 (2, 1) m에 있고 yaw가 90°라면, 로봇 앞 1 m의 점 `(1, 0)`은 map에서 `(2, 2)` m입니다. 먼저 로봇 기준 점을 회전해 `(0, 1)`로 만들고, 로봇 위치 `(2, 1)`을 더합니다.

| 로봇 기준 점 | yaw | 회전한 점 | map 기준 점 |
|---|---|---|---|
| (1, 0) m | 0° | (1, 0) | (3, 1) m |
| (1, 0) m | 90° | (0, 1) | (2, 2) m |

2D 계산은 `x' = cos(yaw) × x − sin(yaw) × y`, `y' = sin(yaw) × x + cos(yaw) × y`입니다. [실행 예제](/education-assets/foundations/basics.py)는 두 번째 점을 계산합니다. RViz의 Fixed Frame은 최종 표시 기준입니다. TF는 `map → odom → base_link → sensor` 사이의 위치·방향 관계를 연결합니다. 센서의 장착 위치는 정적 변환, 이동 중 로봇 위치는 동적 변환입니다.

쿼터니언은 3D 방향을 표현하는 네 값입니다. z축 yaw만 있다면 ROS 메시지의 순서 `(x,y,z,w)`에서 `(0,0,sin(yaw/2),cos(yaw/2))`입니다. yaw 90°는 약 `(0,0,0.7071,0.7071)`이며, 일반적인 3D 회전에는 이 단순식만 쓰지 않습니다.


## F 같은 모터에 P·PI·PID를 적용한다

다음 그래프는 같은 합성 모터 모델을 실제 계산한 결과입니다. 1초에 목표 속도를 1 rad/s로 바꾸고, 4초에 부하를 더했습니다. 위에는 목표·측정 속도, 아래에는 -1~1로 제한한 구동 명령을 함께 그렸습니다.

![합성 모터의 P·PI·PID 속도 응답과 구동 출력](/home/user/MEROsite/private/education-assets/foundations/pid-response.png)

P는 계속 남는 오차가 있어야 구동 출력을 유지합니다. PI는 오차를 누적해 그 차이를 줄이지만 이 계수에서는 목표를 약 25.7% 넘어섭니다. PID는 측정 속도의 변화에 반응해 같은 조건의 오버슈트를 약 18.8%로 줄입니다. D가 항상 개선을 보장하는 것은 아닙니다.

**정상상태 오차**는 충분히 지난 뒤 남는 차이, **오버슈트**는 목표를 넘어선 크기, **정착 시간**은 정해진 오차 범위 안에 들어와 유지하는 데 걸린 시간입니다. 그래프에서 ±2% 같은 범위를 먼저 정하고, 부하가 바뀐 뒤에는 다시 응답을 읽습니다.

[전체 실행 코드](/education-assets/foundations/pid-response.py)를 저장한 폴더에서 실행합니다. Python 3.10 이상과 matplotlib만 필요하며 모터·ROS는 필요 없습니다.

```bash
python -m pip install matplotlib
python pid-response.py --kp 1.2 --ki 4.5 --kd 0.14
```

`results/pid-response.png`, `p.csv`, `pi.csv`, `pid.csv`, 수치 JSON이 생성되면 계산과 결과 저장이 완료된 것입니다. 계수를 하나씩 바꾸고 같은 목표·부하에서 비교합니다. 구동 지연·속도 지연만 둔 합성 모델이므로 실물 게인으로 바로 사용하지 않습니다. [Cart-pole 비교](/education/simulation/mujoco-first-run#cartpole)에서는 이동 범위까지 함께 봅니다.

## G 정책의 관절 목표를 실제 토크로 바꾼다

춤의 참조 모션이나 RL·VLA 정책은 다음 관절 목표를 만들 수 있습니다. 목표 각도를 출력했다고 관절이 그 각도에 도착한 것은 아닙니다. 관절 제어기는 현재 각도·속도를 측정하고, 목표와의 차이로 구동 출력을 만듭니다. 위치 명령을 받는 모터에서는 이 계산의 일부가 모터 내부에 있을 수 있습니다.

```flow LR
모션 또는 정책 -> 관절 목표: 원하는 위치와 속도
관절 목표 -> 관절 제어기: 목표와 실제의 차이
엔코더 -> 관절 제어기: 실제 위치와 속도
관절 제어기 -> 구동기: 토크 또는 전류 명령
구동기 -> 엔코더: 움직임의 결과
```

설명용 토크 PD는 `토크 = Kp × (목표 각도 − 실제 각도) + Kd × (목표 각속도 − 실제 각속도)`입니다. 위치 오차는 가상 스프링처럼, 속도 오차는 가상 감쇠처럼 작용합니다. 현재 0.2 rad, 목표 0.3 rad, 현재 속도 0.5 rad/s, 목표 속도 0인 경우를 계산합니다.

| 항목 | 설명용 계수와 계산 | 토크 |
|---|---|---|
| P | 2 N·m/rad × (0.3 − 0.2) rad | +0.20 N·m |
| D | 0.1 N·m·s/rad × (0 − 0.5) rad/s | −0.05 N·m |
| PD 합 | 목표로 당기되 빠른 접근을 줄임 | +0.15 N·m |
| 출력 제한 ±0.12 N·m | 계산 값이 한계를 넘음 | 실제 명령 +0.12 N·m |

계수에는 단위가 있습니다. PWM 출력의 Kp와 토크 출력의 Kp는 같은 값이 아닙니다. 위 수치는 계산을 위한 예이며, DYNAMIXEL의 raw gain이나 전류 값으로 직접 옮기지 않습니다. MuJoCo의 위치 구동기·관절 감쇠 설정도 이 토크 PD 식과 자동으로 같은 제어기가 되는 것은 아닙니다.

## H 자세 유지와 궤적 추종은 다른 문제다

고정된 자세를 유지할 때는 목표 각도가 일정합니다. 춤에서는 목표가 시간에 따라 바뀌므로 **위치·속도·실행 시각이 있는 궤적**을 따라갑니다. 같은 관절 자세 목록을 두 배 빠르게 재생하면 요구 속도와 가속도가 달라집니다. 점프에서는 이륙과 착지의 시간도 중요합니다.

**피드포워드**는 목표 움직임이나 모델을 보고 필요한 출력을 미리 더하는 것입니다. **피드백**은 실제 오차를 보고 고치는 것입니다. 서로 대체하는 방법이 아니라 역할이 다릅니다.

예를 들어 위치를 추종하되 출력이 관절 속도인 제어기를 생각합니다. 목표가 초당 1 rad씩 움직이고 위치 오차가 0.05 rad, Kp가 4/s라면 피드백은 0.2 rad/s입니다. 목표 속도 1 rad/s를 미리 더하면 명령은 1.2 rad/s입니다. 오차가 0일 때도 움직이는 목표를 따라가려면 속도 명령이 필요하다는 점을 보여줍니다.

토크 제어에서는 자세에 따른 중력 보상 같은 모델 출력을 더할 수 있습니다. 모델이 틀리면 보상도 틀리므로 피드백과 함께 읽습니다. 무거운 물체를 들었을 때 생긴 차이를 위치 오차만으로 보정하는 경우와 예상 중력 토크를 미리 더한 경우를 비교하는 것이 다음 교육 예제입니다. 전신 computed-torque·MPC 구현은 이 입문의 필수 범위에 넣지 않습니다.

## I 접촉·포화·지연이 제어 결과를 바꾼다

위치 제어는 어디로 갈지, 힘·토크 제어는 얼마나 힘을 낼지, **임피던스 제어**는 외력이 가해졌을 때 위치와 힘이 어떻게 함께 변할지를 정하는 관점입니다. 단순 관절의 가상 스프링·감쇠로 임피던스의 출발점을 이해할 수 있지만, 실제 손끝·전신 제어는 좌표 변환과 동역학도 필요합니다.

| 상황 | 먼저 해석할 문제 |
|---|---|
| 춤의 빠른 자세 전환 | 목표 속도·가속도, 추종 오차와 출력 포화 |
| 포복의 팔·몸통 접촉 | 허용 접촉과 마찰, 접촉한 방향의 힘 |
| 사족로봇 착지 | 충격, 관절의 탄성·감쇠 반응과 구동기 한계 |
| RB-Y1으로 물체 잡기 | 팔 위치와 물체 접촉·그리퍼 힘의 서로 다른 역할 |

위치 오차가 커졌다고 Kp만 계속 키우면 접촉할 때 더 큰 힘을 요구할 수 있습니다. 관절 토크를 제한해도 손끝 접촉력이 일정하게 제한되는 것은 아닙니다. 모터의 전류 기반 위치 모드 하나를 전신 임피던스 제어와 같은 뜻으로 읽지 않습니다.

샘플링과 지연도 제어의 일부입니다. 0.02초 동안 각도가 0.01 rad 변했다면 평균 속도는 0.5 rad/s입니다. 시간 간격을 0.002초로 잘못 읽으면 5 rad/s로 계산합니다. 미분은 측정 잡음을 키울 수 있고, 오래된 관측의 보정은 이미 변한 상태에 적용됩니다. 물리 계산·센서·관절 제어·정책·화면의 주기를 각각 구분합니다.

포화 상태에서 적분을 계속 쌓는 windup, 목표를 갑자기 바꿀 때의 과도 응답, 빠른 목표를 따라가지 못하는 지연은 서로 다른 현상입니다. PID 응답 그래프와 Cart-pole 비교에서 오차만 보지 않고 출력·시간·실패 조건까지 함께 읽는 이유입니다.
